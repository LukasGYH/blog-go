# 个人博客系统 — 需求分析说明书

> 作业：第二部分 · Web 应用实战（个人博客）
> 定位：以「需求驱动」方式完成一个可运行的博客站点，**后端服务代码由本人手动编写**，用于练习 GORM + Gin。
> 交付形态：后端骨架 + 完整前端 + 环境配置 + 本文档（需求 / 契约 / 验收 / 练习清单）

---

## 1. 项目概述

### 1.1 背景与目标

在完成 Lesson-02（GORM）与 Lesson-03（Gin）的学习后，需要一个综合项目把所有零散知识点串起来。
本项目以「个人博客」为载体，目标有三：

| 目标 | 说明 |
|------|------|
| 业务目标 | 交付一个可真实运行的博客站点：游客能浏览，作者能写作，管理员能治理内容 |
| 学习目标 | 手动实现后端数据访问层与业务层，把 GORM（关联 / 预加载 / 软删除 / 事务 / 聚合 / 分页 / Hook）与 Gin（路由分组 / 中间件 / 绑定校验 / 统一响应）完整实践一遍 |
| 交付目标 | 环境一键可跑：`go run` 起后端、`npm run dev` 起前端，开箱即有种子数据 |

### 1.2 范围界定

**包含（本期标准版）：**
- 用户注册 / 登录 / JWT 鉴权 / 个人资料
- 文章 CRUD（Markdown 正文）、草稿与发布、浏览量
- 分类管理、标签管理（文章与标签为多对多）
- 评论（两级：评论 + 回复）与评论删除权限
- 分页 + 关键字搜索 + 多维筛选 + 排序
- 归档统计、热门文章、后台概览统计（聚合查询练习）

**不包含（本期明确不做，避免范围蔓延）：**
- 图片 / 附件上传（封面仅存 URL 字符串）
- 点赞、收藏、关注、私信
- 富文本所见即所得编辑器（使用 Markdown 源码 + 实时预览）
- 第三方登录、邮件验证、找回密码
- 全文检索引擎（搜索基于 `LIKE`）
- 多租户、多语言

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 文章（Article） | 博客主体内容，含 Markdown 正文 |
| 分类（Category） | 文章的一级归属，**一篇文章最多属于一个分类** |
| 标签（Tag） | 文章的横向标记，**一篇文章可有多个标签**（多对多） |
| 草稿 / 发布 | 文章状态，草稿仅作者与管理员可见 |
| 软删除 | 使用 `gorm.DeletedAt` 逻辑删除，数据行保留 |
| 卡片（ArticleCard） | 列表页返回的文章精简结构，不含正文 |
| 详情（ArticleDetail） | 详情页返回的文章完整结构，含正文与标签 |

## 2. 角色与权限

| 角色 | 说明 | 权限 |
|------|------|------|
| 游客（Guest） | 未登录用户 | 浏览已发布文章、列表、详情、评论列表、归档、分类/标签列表 |
| 注册用户（User） | 已登录用户 | 游客权限 + 发表评论/回复 + 删除自己的评论 + 写文章 + 管理**自己的**文章 + 修改本人资料 |
| 管理员（Admin） | `role = admin` | 用户权限 + 管理**任意**文章 + 分类/标签的增删改 + 评论隐藏/删除 + 查看后台统计 |

**越权规则（后端必须强制校验，不能只靠前端隐藏按钮）：**

| 操作 | 允许者 |
|------|--------|
| 修改 / 删除文章 | 文章作者 或 管理员 |
| 修改文章状态（草稿↔发布） | 文章作者 或 管理员 |
| 删除评论 | 评论作者 或 文章作者 或 管理员 |
| 分类 / 标签 增删改 | 仅管理员 |
| 查看草稿 | 文章作者 或 管理员 |

## 3. 功能需求

### 3.1 用户与认证模块

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| U-01 | 注册 | 用户名 / 邮箱全局唯一；密码 bcrypt 加密存储；注册成功默认 `role=user` | P0 |
| U-02 | 登录 | 用户名 + 密码换取 JWT；返回 token 与用户信息 | P0 |
| U-03 | 鉴权 | 受保护接口校验 `Authorization: Bearer <token>`，解析出用户身份写入上下文 | P0 |
| U-04 | 查看本人信息 | 返回当前登录用户资料 | P0 |
| U-05 | 修改本人资料 | 可改昵称 / 邮箱 / 头像 URL / 个人简介；邮箱改后仍需唯一 | P1 |
| U-06 | 修改密码 | 校验旧密码正确后，写入新密码密文 | P1 |
| U-07 | 退出登录 | 前端清除本地 token（后端无状态） | P2 |

**业务规则：**
- 用户名：3–20 字符，字母数字下划线；邮箱：合法邮箱格式；密码：6–32 位。
- 注册时用户名或邮箱重复 → `409 Conflict`。
- 登录失败统一返回 `401`，**不区分**「用户不存在」与「密码错误」（防用户枚举）。
- 被禁用用户（`status=disabled`）登录 → `403`。

### 3.2 分类管理模块

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| C-01 | 分类列表 | 公开接口，返回分类及其文章数（`article_count`） | P0 |
| C-02 | 新增分类 | 管理员；名称唯一；`slug` 未传则由名称自动生成 | P0 |
| C-03 | 修改分类 | 管理员；改后名称 / slug 仍需唯一 | P1 |
| C-04 | 删除分类 | 管理员；**该分类下仍有文章时禁止删除**，返回 `409` | P1 |

### 3.3 标签管理模块

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| T-01 | 标签列表 | 公开；支持按名称关键字模糊搜索；返回文章数 | P0 |
| T-02 | 新增 / 修改 / 删除标签 | 管理员；名称唯一；硬删除（同时清理关联表） | P1 |

### 3.4 文章管理模块（核心）

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| A-01 | 文章列表 | 分页 + 关键字（标题/摘要）+ 分类 + 标签 + 作者 + 状态筛选 + 排序（最新 / 最热） | P0 |
| A-02 | 文章详情 | 按 ID 查询；预加载作者、分类、标签；游客仅能看已发布文章 | P0 |
| A-03 | 浏览量自增 | 浏览详情时 `view_count + 1`；推荐用原子 SQL 表达式而非「读-改-写」 | P0 |
| A-04 | 新建文章 | 标题 / 正文必填；可指定分类与多个标签；可存为草稿 | P0 |
| A-05 | 编辑文章 | 仅作者或管理员；可更换分类与标签集合 | P0 |
| A-06 | 删除文章 | 仅作者或管理员；**软删除** | P0 |
| A-07 | 切换状态 | 草稿 ↔ 发布；首次发布时写入 `published_at` | P0 |
| A-08 | 归档统计 | 按「年-月」聚合已发布文章数量 | P1 |
| A-09 | 热门文章 | 按浏览量倒序取 N 篇 | P1 |

**业务规则：**
- `slug` 全局唯一：未传时由标题生成（中文标题降级为 `article-<时间戳>`），冲突时追加 `-1`、`-2`。
- 摘要（`summary`）未填时，从正文截取前 120 个字符自动生成。
- 文章与标签的关联写入/更新必须**在事务内**完成（先清旧关联，再写新关联）。
- 删除分类前需校验该分类下无文章；删除标签需校验（或允许级联清理 join 表）。

### 3.5 评论模块

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| M-01 | 评论列表 | 按文章分页查询顶层评论，每条顶层评论内嵌其回复（最多两级） | P0 |
| M-02 | 发表评论 | 登录用户；正文 1–500 字 | P0 |
| M-03 | 回复评论 | `parent_id` 指向顶层评论；若父评论本身是回复，则归并到其顶层父评论 | P1 |
| M-04 | 删除评论 | 评论作者 / 文章作者 / 管理员；软删除；删除顶层评论时同时软删除其回复 | P1 |

**业务规则：**
- 发表评论前必须校验：文章存在且为已发布状态。
- `parent_id` 必须属于同一篇文章，否则返回 `400`。

### 3.6 统计模块（后台概览）

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| S-01 | 概览统计 | 文章总数 / 已发布 / 草稿 / 用户数 / 评论数 / 分类数 / 标签数 | P1 |
| S-02 | 分类维度统计 | 每个分类下的文章数（`GROUP BY` 聚合） | P1 |

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 接口规范 | 统一响应体 `{code, message, data, error}`；统一分页体 `{list, total, page, page_size}`；RESTful 路径，统一 `/api/v1` 前缀 |
| 状态码 | 200 成功 / 201 创建成功 / 400 参数错误 / 401 未认证 / 403 无权限 / 404 不存在 / 409 冲突 / 422 校验失败 / 500 服务端错误 |
| 安全 | 密码 bcrypt；JWT 有效期 24h；越权校验在后端强制；不接受前端传入的 `user_id`（以 token 身份为准） |
| 校验 | 所有入参 DTO 使用 `binding` tag 校验；`page_size` 上限 50，默认 10；`page` 最小 1 |
| 性能 | 列表查询必须 `Preload` 关联，禁止在循环内查库（N+1）；列表字段裁剪（不返回 `content`） |
| 可观测 | 请求日志（方法、路径、状态码、耗时）；panic 恢复中间件；启动时打印监听地址与数据库路径 |
| 一致性 | 多表写入必须包事务；并发更新使用 `gorm.Expr` 表达式或行锁 |
| 可测试 | 核心业务可在 SQLite 内存库上跑 `go test` |
| 兼容性 | Go ≥ 1.22；Node ≥ 18；SQLite 3；浏览器 Chrome / Safari 最新版 |

## 5. 数据模型

### 5.1 实体关系（ER）

```
User 1 ──── N Article          （author_id）
User 1 ──── N Comment          （user_id）
Category 1 ── N Article        （category_id）
Article N ──── N Tag           （中间表 article_tags）
Article 1 ──── N Comment       （article_id）
Comment 1 ──── N Comment       （parent_id，自关联，两级）
```

### 5.3 业务枚举

| 枚举 | 取值 | 定义位置 |
|------|------|----------|
| 用户角色 | `user` / `admin` | `constant/role.go` |

## 6. API 契约（冻结版）

- Base URL：`http://localhost:8080/api/v1`
- 认证方式：`Authorization: Bearer <token>`
- 时间格式：RFC3339（`2026-11-06T15:04:05+08:00`）

### 6.0 通用响应

```json
// 成功
{ "code": 200, "message": "success", "data": { } }

// 失败
{ "code": 409, "message": "username already exists", "error": "username already exists" }

// 分页 data 结构
{ "list": [], "total": 0, "page": 1, "page_size": 10 }
```

### 6.1 认证

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/auth/register` | 否 | 注册 |
| POST | `/auth/login` | 否 | 登录 |
| GET | `/auth/me` | 是 | 当前用户 |
| PUT | `/auth/me` | 是 | 修改资料 |
| PUT | `/auth/password` | 是 | 修改密码 |

```jsonc
// POST /auth/register 请求
{ "username": "lukas", "email": "lukas@example.com", "password": "123456", "nickname": "Lukas" }
// → 201 data: { "id": 1, "username": "lukas", "email": "lukas@example.com", "nickname": "Lukas", "role": "user" }

// POST /auth/login 请求
{ "username": "lukas", "password": "123456" }
// → 200 data: { "token": "eyJ...", "expires_at": "2026-11-07T15:04:05+08:00",
//               "user": { "id": 1, "username": "lukas", "nickname": "Lukas", "avatar": "", "role": "user" } }

// PUT /auth/me 请求（字段均可选）
{ "nickname": "新昵称", "email": "new@example.com", "avatar": "https://...", "bio": "Go 学习中" }

// PUT /auth/password 请求
{ "old_password": "123456", "new_password": "654321" }
```

### 6.2 分类

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/categories` | 否 | 分类列表（含 article_count） |
| POST | `/categories` | 管理员 | 新增 |
| PUT | `/categories/:id` | 管理员 | 修改 |
| DELETE | `/categories/:id` | 管理员 | 删除（有文章 → 409） |

```jsonc
// GET /categories → 200
{ "code":200, "data": [ { "id":1, "name":"Go 语言", "slug":"go", "description":"", "sort_order":0, "article_count":3 } ] }

// POST /categories 请求
{ "name": "后端工程", "slug": "backend", "description": "服务端相关", "sort_order": 10 }
```

### 6.3 标签

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/tags?keyword=` | 否 | 标签列表（含 article_count） |
| POST | `/tags` | 管理员 | 新增 |
| PUT | `/tags/:id` | 管理员 | 修改 |
| DELETE | `/tags/:id` | 管理员 | 删除 |

```jsonc
// POST /tags 请求
{ "name": "GORM" }
// → 201 data: { "id": 5, "name": "GORM", "slug": "gorm" }
```

### 6.4 文章

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/articles` | 否 | 列表（分页 + 筛选） |
| GET | `/articles/:id` | 否 | 详情（草稿仅作者/管理员可见） |
| POST | `/articles` | 是 | 新建 |
| PUT | `/articles/:id` | 作者/管理员 | 编辑 |
| PATCH | `/articles/:id/status` | 作者/管理员 | 切换状态 |
| DELETE | `/articles/:id` | 作者/管理员 | 软删除 |
| GET | `/articles/archive` | 否 | 归档统计 |
| GET | `/articles/hot?limit=5` | 否 | 热门文章 |

**列表查询参数：**

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| page | int | 1 | 页码 |
| page_size | int | 10 | 每页条数（≤50） |
| keyword | string | - | 匹配标题或摘要 |
| category_id | uint | - | 分类筛选 |
| tag_id | uint | - | 标签筛选 |
| author_id | uint | - | 作者筛选 |
| status | string | - | `draft`/`published`；非作者/管理员时强制按 `published` |
| sort | string | latest | `latest` / `hot` |

```jsonc
// GET /articles?page=1&page_size=10&keyword=gorm&sort=latest → 200
{ "code":200, "data": {
  "list": [{
    "id": 1, "title": "GORM 关联与预加载", "slug": "gorm-preload",
    "summary": "本文整理 GORM 的关联查询……", "cover_image": "",
    "status": "published", "view_count": 42,
    "published_at": "2026-11-01T10:00:00+08:00", "created_at": "2026-11-01T09:50:00+08:00",
    "author":   { "id":1, "username":"lukas", "nickname":"Lukas", "avatar":"" },
    "category": { "id":1, "name":"Go 语言", "slug":"go" },
    "tags":     [ { "id":1, "name":"GORM", "slug":"gorm" } ],
    "comment_count": 3
  }],
  "total": 1, "page": 1, "page_size": 10 } }

// GET /articles/1 → 200 data: 在卡片字段基础上增加
{ "content": "# 标题\n\n正文 Markdown", "updated_at": "2026-11-02T10:00:00+08:00",
  "category": {...}, "tags": [...], "author": {...} }

// POST /articles 请求
```

## 7. 前端设计

### 7.1 技术选型

Vue 3（`<script setup>`）+ Vite + Element Plus + Vue Router 4 + Pinia + Axios + markdown-it（+ highlight.js 代码高亮）

### 7.2 路由与页面

| 路由 | 页面 | 鉴权 | 说明 |
|------|------|------|------|
| `/` | 首页 | 否 | 文章卡片流 + 关键字搜索 + 分类/标签筛选 + 排序 + 分页；右侧栏展示分类、标签、热门文章、归档 |
| `/article/:id` | 文章详情 | 否 | Markdown 渲染、作者/分类/标签、浏览量、评论区（发表 / 回复 / 删除） |
| `/login` | 登录 | 否 | |
| `/register` | 注册 | 否 | |
| `/editor` | 新建文章 | 是 | Markdown 编辑 + 实时预览 + 分类/标签选择 + 草稿/发布 |
| `/editor/:id` | 编辑文章 | 是（作者） | 同上，回填数据 |
| `/me` | 个人中心 | 是 | 我的文章（含草稿）管理、资料修改、改密码 |
| `/admin` | 后台 | 管理员 | 概览统计卡片、分类管理、标签管理 |
| `/archive` | 归档 | 否 | 按年月展开文章列表 |

### 7.3 关键交互约定

- Axios 请求拦截器自动注入 `Authorization`；响应拦截器统一剥壳：`code !== 200/201` 弹 `ElMessage.error(message)` 并 reject。
- 401 时清空本地 token 并跳转 `/login`。
- Pinia `userStore` 持久化 token 与用户信息到 `localStorage`。
- 列表页筛选条件与分页**同步到 URL query**，刷新不丢失。
- 前端仅做体验层隐藏（未登录不显示「写文章」），**权限以服务端为准**。
- 骨架统一由 Element Plus（`ElSkeleton` / `v-loading`）承载，避免白屏。

### 7.4 接口未实现时的降级表现

后端骨架中 **Article / Tag / Comment / Stats 模块的 Service 未实现**（返回 `501`）。前端遇 `501` 时应展示后端返回的提示文案（如「功能待实现：ArticleService.List」）而非报错崩溃，便于边写后端边联调。

### 10.1 交付划分（重要）

### 10.2 验收标准

**基础（P0）：**
1. `make run` 启动后端，控制台打印监听地址；`GET /health` 返回 `ok`。
2. `npm run dev` 启动前端，首页可加载文章列表（分页、搜索、筛选均生效）。
3. 可注册、登录；未登录访问受保护接口返回 401。
4. 登录用户可新建文章（草稿 / 发布），编辑、删除自己的文章成功；他人文章返回 403。
5. 文章详情展示 Markdown 渲染结果，浏览量随刷新自增。
6. 发表评论与回复成功，评论作者 / 文章作者 / 管理员可删除评论。
7. 管理员可管理分类与标签；删除仍有文章的分类返回 409。
8. 所有列表接口分页参数生效，`page_size > 50` 被裁剪为 50。

**进阶（P1）：**
9. 归档统计、热门文章、后台概览统计（聚合查询）返回正确结果。
10. 列表接口 SQL 数量恒定（不随数据量线性增长）——证明无 N+1。
11. `go test ./...` 通过（至少覆盖：文章列表分页查询、文章创建事务、评论树组装）。
12. 软删除生效：删除文章后 `articles` 表仍有行且 `deleted_at` 非空，但接口查不到。

**扣分项：**
- 业务代码出现裸字符串状态（未使用常量）
- 在 Handler 里直接操作 `*gorm.DB`
- 多表写入未使用事务
- 分页直接 `Find` 后手动切片

## 12. 风险与注意事项

| 风险 | 影响 | 应对 |
|------|------|------|
| CGO 编译 SQLite 首次耗时 / 报错 | 起不来 | 已用 `goproxy.cn`；如报 SDK 错误，重装 CommandLineTools；实在不行换纯 Go 驱动 `github.com/glebarez/sqlite` |
| SQLite 不支持行级锁 / `FOR UPDATE` | 高并发练习点缺失 | 本期用 `gorm.Expr` 原子自增替代；如需并发扣减练习可切 MySQL（Docker 已就绪） |
| 越权校验遗漏 | 安全事故 | 统一在 Service 层做「当前用户 vs 资源归属」判定，禁止信任前端 |
| 多对多关联更新方式不当 | 关联丢失 / 重复 | 先在事务内 `Association("Tags").Clear()` 再 `Replace` |
| 前端先于后端完成 | 联调阻塞 | 后端骨架先保证 501 语义正确 + 种子数据齐全，前端对 501 做降级提示 |
| 分页查询 SQL 数量随数据增长 | N+1 | 用 `Preload` 而非循环内查询；列表不返回 `content` 大字段 |
